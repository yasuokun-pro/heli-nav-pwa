# 他機情報の中継 (Cloudflare Workers)

## なぜ要るか
`adsb.lol` と `adsb.fi` は無料・登録不要で日本上空のデータを返すが、
**`Access-Control-Allow-Origin` を返さない**。そのため GitHub Pages に置いた
PWA から直接 `fetch` すると、通信そのものは成立してもブラウザが結果を渡してくれない
(`no-cors` で投げると `type=opaque` になることで確認済み)。
`airplanes.live` は 2026-09 から寄与者限定になり 403。OpenSky は自サイト限定の CORS。

つまり **静的ページである限り、どの提供元を選んでも同じ壁**に当たる。
1枚だけ中継を挟んで CORS ヘッダを付け直すのが、お金をかけない唯一の解。

## 置き方 (ブラウザだけで完結する。Node も wrangler も要らない)

1. <https://dash.cloudflare.com/> で無料アカウントを作る。**支払い方法の登録は不要**。
2. 左メニューの **Workers & Pages** → **Create** → **Start with Hello World!** → **Deploy**。
3. **Edit code** を開き、中身を全部消して [`adsb-relay.js`](adsb-relay.js) を貼り付け → **Deploy**。
4. Worker の **Settings** → **Variables and Secrets** → **Add**
   - 種類: **Secret**
   - 名前: `RELAY_KEY`
   - 値: 適当に長い文字列(例: `openssl rand -hex 24` の出力)
   → **Deploy**
5. 払い出された `https://<名前>.<アカウント>.workers.dev` が中継URL。

## アプリ側
「他機」タブの **他機情報の中継設定** に、中継URLと合言葉を入れて保存する。
**端末の localStorage に入るだけで、リポジトリには一切書かれない**。
(公開リポジトリに合言葉を置くと、対策の意味が無くなる)

## 守りの4枚
| | 何をするか | 効き方 |
|---|---|---|
| Origin 照合 | `ALLOW` に書いた配信元だけ通す | ブラウザ以外・他サイトからの利用を弾く |
| 合言葉 `k=` | `RELAY_KEY` と一致しなければ 403 | URLを拾われただけでは使えない |
| IPごとの上限 | 1分12回を超えたら 429 | 1つの発信元に枠を食い潰させない |
| 上流キャッシュ | 位置を0.05度に丸めて10秒保持 | **adsb.lol 側の負荷**を下げる |

⚠ 上流キャッシュが減らすのは adsb.lol の負荷であって、**Cloudflare のリクエスト数ではない**。
Worker が動く以上そのまま数えられる。

⚠ Origin ヘッダはブラウザ以外からは詐称できる。合言葉と併用して初めて意味がある。

## 無料枠
1日 **100,000 リクエスト**、CPU は1リクエスト 10ms まで。素通しの中継は CPU をほぼ使わない。
15秒に1回なら1時間240回なので、のべ **417時間/日** 使える。

超えても **課金にはならない**。`Error 1027` を返して止まり、
**00:00 UTC = 日本時間の朝9時**にリセットされる。
午前中に使い切るとその日の飛行時間帯はまるごと死ぬので、上限には余裕を持たせてある。

## 出典表記
`adsb.lol` / `adsb.fi` は有志運営。アプリの他機一覧に取得元名を出し続けること。
